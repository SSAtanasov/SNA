# D02-04: DNS – имена вместо числа

> **Поток:** начинаещи | **Време:** ~60 мин | **Среда:** Cisco Packet Tracer 8.2.2
> **Задължителен минимум:** Части 1–4. **Разширение:** Част 5.
> **Връзка с курса:** лекция D01-03 (услуги на приложния слой: DNS); държавен въпрос 12.
> **Начало:** отворете `D02-03_YourName.pkt` и го запазете като `D02-04_YourName.pkt`.
> **Ако изоставате:** започнете от готовия начален файл `D02-04_Start.pkt` от преподавателя.

## Какво ще направите

Ще добавите DNS сървър, ще му въведете имената на устройствата и ще проверите, че компютрите достигат устройствата по име. Ще видите и най-важното различие при диагностиката: **„по IP адрес работи, по име – не“**.

## Кратка теория

**DNS (Domain Name System)** превръща имената в IP адреси – като телефонен указател: търсите по име, получавате номер.

```
PC1: „Кой е адресът на server.company.local?“  →  DNS сървър
DNS сървър: „192.168.10.2“                       →  PC1
PC1 изпраща пакета до 192.168.10.2
```

| Запис | Какво съдържа | Пример |
|-------|---------------|--------|
| **A** | Име → IPv4 адрес | `server.company.local` → `192.168.10.2` |
| **CNAME** | Псевдоним → друго име | `www.company.local` → `web.company.local` |

DNS запитването пътува по **UDP порт 53**. Компютрите вече знаят адреса на DNS сървъра – дадохме им го с DHCP в D02-03 (`dns-server 192.168.10.2`).

> В Packet Tracer DNS сървърът поддържа записи A, CNAME, SOA и NS. Записи MX и PTR не могат да се създадат.

## Част 1: Добавяне на DNS сървъра (15 мин)

**a.** Добавете **Server-PT** и го свържете към **SW1 FastEthernet0/11**.

**b.** Портът на комутатора – във VLAN 10:

```cisco
SW1# configure terminal
SW1(config)# interface FastEthernet0/11
SW1(config-if)# switchport mode access
SW1(config-if)# switchport access vlan 10
SW1(config-if)# description DNS-Server
SW1(config-if)# end
SW1# copy running-config startup-config
```

**c.** Server → **Desktop** → **IP Configuration** → **Static**:

```
IP Address:      192.168.10.2
Subnet Mask:     255.255.255.0
Default Gateway: 192.168.10.1
DNS Server:      127.0.0.1
```

## Част 2: Записите в DNS (15 мин)

Server → **Services** → **DNS** → **DNS Service: On**.

Добавете записи (Name, Type, Address → **Add**):

| Name | Type | Address / Host Name |
|------|------|---------------------|
| server.company.local | A Record | 192.168.10.2 |
| router.company.local | A Record | 192.168.10.1 |
| switch.company.local | A Record | 192.168.99.2 |
| web.company.local | A Record | 192.168.10.3 |
| www.company.local | CNAME | web.company.local |

> За CNAME Packet Tracer показва поле **Host Name** – въведете каноничното име, а не IP адрес.

## Част 4: „По IP работи, по име – не“ (15 мин)

### Стъпка 1: DNS в Simulation

**a.** Превключете на **Simulation**, филтри **DNS** и **ICMP**.

**b.** От PC1: `ping router.company.local`. Натискайте **Capture/Forward**.

| Въпрос | Отговор |
|--------|---------|
| Кой пакет тръгва първи – DNS или ICMP? | |
| Source и Destination IP на DNS заявката | |
| Транспортен протокол и порт (таб **OSI Model**, слой 4) | |
| Към кой адрес отива ICMP пакетът след DNS отговора? | |

### Стъпка 2: Изключете DNS услугата

**a.** Върнете се в **Realtime**. На сървъра: **Services** → **DNS** → **Off**.

**b.** От **PC2** – той още не е търсил името `router.company.local`:

```
C:\> ping router.company.local
C:\> ping 192.168.10.1
```

> Проверяваме от компютър, който не е питал за това име. Ако компютърът пази в кеша си отговора от Стъпка 1, ping по име може да успее и при изключен DNS – тогава тестът не показва нищо.

_Кой ping успява и кой не? Какво показва това за мястото на проблема и какво **не** показва?_ ______

**c.** Включете DNS услугата отново (**On**) и проверете, че името се разрешава.

<details markdown="1">
<summary>Отговори за самопроверка</summary>

- DNS заявката тръгва **първа**: компютърът трябва да научи адреса, преди да изпрати ICMP. Тя е от PC1 до **192.168.10.2**, по **UDP порт 53**. После ICMP отива до **192.168.10.1**.
- PC3 също разрешава имената: DNS сървърът е във VLAN 10, но R1 маршрутизира между VLAN-ите.
- При изключен DNS ping по **име** не успява („could not find host“), а ping по **IP** успява. Това насочва към разрешаването на имена: DNS услугата, записите или DNS настройката на компютъра. Не доказва, че всичко останало в мрежата е изправно – доказва само, че пътят до 192.168.10.1 работи.

</details>

## Запомнете

- DNS превежда имена в IP адреси; запитването е по UDP порт 53.
- Записът A дава адрес; записът CNAME дава друго име.
- „По IP работи, по име – не“ насочва към разрешаването на имена (DNS), а не към свързаността до този адрес.
