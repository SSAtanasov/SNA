# D02-03: DHCP – адресите се раздават сами

> **Поток:** начинаещи | **Време:** ~60 мин | **Среда:** Cisco Packet Tracer 8.2.2
> **Задължителен минимум:** Части 1–4. **Разширение:** Част 5.
> **Връзка с курса:** лекция D01-03 (услуги на приложния слой: DHCP); държавен въпрос 12 (DHCP, lease).
> **Начало:** отворете `D02-02_YourName.pkt` и го запазете като `D02-03_YourName.pkt`.
> **Ако изоставате:** започнете от готовия начален файл `D02-03_Start.pkt` от преподавателя.

## Какво ще направите

До сега всеки адрес въвеждахте на ръка. Сега маршрутизаторът R1 ще раздава автоматично адрес, маска, шлюз и DNS сървър на всички компютри. Ще видите в Simulation четирите съобщения на DHCP.

## Кратка теория

**DHCP (Dynamic Host Configuration Protocol)** раздава мрежовите настройки автоматично. Обменът има четири стъпки – **DORA**:

```
1. Discover  – Компютърът: „Има ли тук DHCP сървър?“        (broadcast)
2. Offer     – Сървърът:   „Предлагам ти 192.168.10.11.“
3. Request   – Компютърът: „Приемам този адрес.“            (broadcast)
4. Acknowledge – Сървърът: „Потвърдено. Ползвай го до …“
```

- **Pool** – набор адреси за една мрежа (по един за всеки VLAN).
- **Excluded addresses** – адреси, които DHCP **не** раздава, защото са запазени за маршрутизатори, сървъри и принтери.
- **Lease** – срокът, за който адресът е даден.

| Адрес в мрежата | За какво е запазен |
|-----------------|--------------------|
| .1 | Шлюзът (R1) |
| .2 | DNS сървърът (ще го добавим в D02-04) |
| .3–.10 | Други сървъри и устройства |
| .11 и нагоре | Раздават се от DHCP |

## Част 1: DHCP на R1 (20 мин)

```cisco
R1> enable
R1# configure terminal
R1(config)# ip dhcp excluded-address 192.168.10.1 192.168.10.10
R1(config)# ip dhcp excluded-address 192.168.20.1 192.168.20.10
R1(config)# ip dhcp pool ADMIN_POOL
R1(dhcp-config)# network 192.168.10.0 255.255.255.0
R1(dhcp-config)# default-router 192.168.10.1
R1(dhcp-config)# dns-server 192.168.10.2
R1(dhcp-config)# exit
R1(config)# ip dhcp pool IT_POOL
R1(dhcp-config)# network 192.168.20.0 255.255.255.0
R1(dhcp-config)# default-router 192.168.20.1
R1(dhcp-config)# dns-server 192.168.10.2
R1(dhcp-config)# end
R1# copy running-config startup-config
```

| Команда | Какво прави |
|---------|-------------|
| `ip dhcp excluded-address` | Тези адреси не се раздават |
| `ip dhcp pool ADMIN_POOL` | Създава pool за VLAN 10 |
| `network` | Мрежата, от която се раздава |
| `default-router` | Шлюзът, който получава компютърът |
| `dns-server` | DNS сървърът (той ще заработи в D02-04) |

## Част 3: DORA в Simulation (20 мин)

**a.** Превключете на **Simulation**. В **Edit Filters** оставете само **DHCP**.

**b.** От PC1 → **Command Prompt**:

```
C:\> ipconfig /release
C:\> ipconfig /renew
```

**c.** Натискайте **Capture/Forward** и отваряйте всеки DHCP пакет. Попълнете:

| Съобщение | Source IP | Destination IP | Кой го изпраща |
|-----------|-----------|----------------|----------------|
| Discover | | | |
| Offer | | | |
| Request | | | |
| ACK | | | |

**d.** Отворете таб **OSI Model** на Discover.

_На кой слой е DHCP? По кой транспортен протокол и порт пътува?_ ______

<details markdown="1">
<summary>Отговори за самопроверка</summary>

- Първият компютър, поискал адрес във VLAN 10, обикновено получава **192.168.10.11** – първия неизключен адрес. Кой компютър ще е първи, зависи от реда на превключване; затова работим с адресите от таблицата, а не с предварително зададени.
- **Discover** и **Request** са от `0.0.0.0` до `255.255.255.255`: компютърът още няма адрес и не знае къде е сървърът. Offer и ACK ги изпраща R1 (192.168.10.1).
- DHCP е на **приложния слой (7)**, пътува по **UDP**, портове 68 (клиент) и 67 (сървър).

</details>

## Част 5 (разширение): Когато DHCP не отговаря

Запазете копие на файла като `D02-03_Extra_YourName.pkt` и работете в него.

**a.** На R1 изтрийте pool-а за IT:

```cisco
R1(config)# no ip dhcp pool IT_POOL
```

**b.** На PC3 изпълнете `ipconfig /release` и `ipconfig /renew`, после `ipconfig`.

- _Какъв адрес получава PC3? От коя мрежа е той?_ ______
- _Може ли PC3 да ping-не шлюза си 192.168.20.1? Защо?_ ______

**c.** Проверете дали срокът на адреса се задава на R1: в режима на pool `R1(dhcp-config)# lease ?`. Ако командата съществува, задайте `lease 0 8` (8 часа) и обяснете кога бихте избрали кратък и кога дълъг срок.

<details markdown="1">
<summary>Отговор за самопроверка</summary>

PC3 получава адрес от **169.254.0.0/16** (APIPA) – Windows го задава сам, когато DHCP сървър не отговори. Този адрес не е в мрежата 192.168.20.0/24, затова шлюзът е недостъпен.

</details>

## Запомнете

- DHCP раздава адрес, маска, шлюз и DNS сървър; обменът е DORA.
- Компютър без адрес говори от `0.0.0.0` към `255.255.255.255`.
- Адрес 169.254.x.x означава: „DHCP сървър не отговори“.
