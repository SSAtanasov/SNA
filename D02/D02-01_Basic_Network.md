# D02-01: Първата мрежа – Router, Switch и три компютъра

> **Поток:** начинаещи | **Време:** ~100 мин | **Среда:** Cisco Packet Tracer 8.2.2
> **Задължителен минимум:** Части 1–6. **Разширение:** Част 7.
> **Връзка с курса:** лекции D01-01-02 (физически слой, кабели), D01-02 (модели и PDU), D02-02 (Ethernet, MAC, комутация), D02-03 (IPv4, маска, шлюз), D01-04 (ping); държавни въпроси 10, 11, 13 и 14.
> **Начало:** нов празен файл. **Запазете накрая като:** `D02-01_YourName.pkt` – от него започва D02-02.

## Какво ще направите

Ще изградите малка мрежа: един маршрутизатор, един комутатор и три компютъра. Ще ги конфигурирате, ще проверите дали „се чуват“ и ще видите в режим **Simulation** какво точно пътува по кабелите.

## Кратка теория (прочетете преди работа)

| Устройство | Слой | Какво прави | Аналогия |
|------------|------|-------------|----------|
| **Switch (комутатор)** | 2 | Свързва устройствата в **една** мрежа и препраща рамките по MAC адрес | Телефонна централа в една сграда |
| **Router (маршрутизатор)** | 3 | Свързва **различни** мрежи и решава накъде да изпрати пакета по IP адрес | Пощенски служител между кварталите |

**IP адрес и маска.** IP адресът `192.168.1.10` с маска `255.255.255.0` (/24) се чете така: първите три числа (`192.168.1`) са **мрежата**, последното (`.10`) е **устройството**. Всички устройства в една мрежа имат еднаква мрежова част и еднаква маска.

**Default gateway (шлюз).** Адресът на маршрутизатора в локалната мрежа. Когато компютърът изпраща към адрес **извън** своята мрежа, той изпраща рамката до шлюза.

**MAC адрес.** Хардуерният адрес на мрежовата карта (например `0001.6458.2501`). Комутаторът работи с MAC адреси, маршрутизаторът – с IP адреси. **ARP** намира MAC адреса по известен IP адрес.

## Част 1: Изграждане на топологията (15 мин)

**Устройства:** 1× Router **2911** (R1), 1× Switch **2960** (SW1), 3× **PC** (PC1, PC2, PC3).

**Кабели:** Copper Straight-Through (плътна черна линия).

```
R1  GigabitEthernet0/0  ↔  SW1  FastEthernet0/1
SW1 FastEthernet0/2     ↔  PC1  FastEthernet0
SW1 FastEthernet0/3     ↔  PC2  FastEthernet0
SW1 FastEthernet0/4     ↔  PC3  FastEthernet0
```

```
              [R1] 192.168.1.1
                |  Gi0/0
                |  Fa0/1
              [SW1] 192.168.1.2
             /   |   \
         Fa0/2 Fa0/3 Fa0/4
          /      |      \
      [PC1]    [PC2]    [PC3]
      .10      .11      .12        Мрежа 192.168.1.0/24
```

> **Наблюдение:** След свързването триъгълниците на връзката към R1 са **червени**, а към компютрите стават **зелени**. Защо? Отговорът е в Част 2.

## Част 2: Конфигурация на маршрутизатора (20 мин)

Кликнете R1 → таб **CLI** → Enter. На въпроса `initial configuration dialog?` напишете `no`.

```cisco
Router> enable
Router# configure terminal
Router(config)# hostname R1
R1(config)# no ip domain-lookup
R1(config)# enable secret class123
R1(config)# line console 0
R1(config-line)# password cisco
R1(config-line)# login
R1(config-line)# logging synchronous
R1(config-line)# exit
R1(config)# interface GigabitEthernet0/0
R1(config-if)# ip address 192.168.1.1 255.255.255.0
R1(config-if)# description Connection to SW1
R1(config-if)# no shutdown
R1(config-if)# end
R1# copy running-config startup-config
```

| Команда | Какво прави |
|---------|-------------|
| `enable` | Влиза в привилегирован режим (`R1#`) |
| `configure terminal` | Влиза в режим за конфигуриране (`R1(config)#`) |
| `hostname R1` | Задава име на устройството |
| `no ip domain-lookup` | При грешно написана команда не чака DNS |
| `enable secret` / `password` + `login` | Пароли за привилегирования режим и за конзолата |
| `ip address` | Адрес и маска на интерфейса |
| `no shutdown` | **Включва** интерфейса. Интерфейсите на маршрутизатора са изключени по подразбиране – затова триъгълникът беше червен |
| `copy running-config startup-config` | Записва конфигурацията (иначе се губи при рестарт) |

> Паролите `class123` и `cisco` са само за упражнението.

## Част 3: Конфигурация на комутатора (15 мин)

Кликнете SW1 → **CLI**:

```cisco
Switch> enable
Switch# configure terminal
Switch(config)# hostname SW1
SW1(config)# no ip domain-lookup
SW1(config)# enable secret class123
SW1(config)# line console 0
SW1(config-line)# password cisco
SW1(config-line)# login
SW1(config-line)# exit
SW1(config)# interface vlan 1
SW1(config-if)# ip address 192.168.1.2 255.255.255.0
SW1(config-if)# no shutdown
SW1(config-if)# exit
SW1(config)# ip default-gateway 192.168.1.1
SW1(config)# end
SW1# copy running-config startup-config
```

**Защо комутаторът има IP адрес?** За да рамкира трафика, той не му трябва. Адресът на `interface vlan 1` служи само за **управлението** на комутатора от разстояние (ping, SSH). Това е основата на мрежовото администриране и ще го развием в D02-07.

### Стъпка 2: Какво пътува по кабела (режим Simulation)

**b.** Превключете долу вдясно на **Simulation**. В **Edit Filters** оставете само **ARP** и **ICMP**.

**c.** От PC1 изпълнете `ping 192.168.1.12` и натискайте **Capture/Forward**.

**d.** Кликнете на плика (PDU) при всяко устройство и попълнете:

### Стъпка 3: Проверка на устройствата

```cisco
R1# show ip interface brief
SW1# show ip interface brief
R1# show arp
```

_Какво означава `up / up` и какво `administratively down / down`?_ ______

<details markdown="1">
<summary>Отговори за самопроверка</summary>

- Първият ping може да изтече, защото компютърът първо изпраща **ARP** заявка, за да научи MAC адреса. Докато чака, първият ICMP пакет закъснява.
- ARP заявката е **broadcast** (`FFFF.FFFF.FFFF`) и SW1 я копира до всички портове освен входящия. Отговаря само PC3 – с **unicast** до PC1.
- ARP е между слой 2 и слой 3 (Packet Tracer го показва на слой 2); ICMP е на слой 3.
- В IP заглавката на ICMP пакета: source 192.168.1.10, destination 192.168.1.12; **Protocol = 1** означава ICMP (TCP е 6, UDP е 17). TTL е стойността, с която PC1 изпраща пакета; тук няма маршрутизатор по пътя, затова тя не се променя.
- `up / up` = кабелът е свързан и интерфейсът работи; `administratively down` = интерфейсът е изключен с `shutdown` (или не е включен с `no shutdown`).

</details>

## Част 6: Колко адреса има една мрежа (15 мин)

**a.** Попълнете за мрежата на упражнението:

| | 192.168.1.0/24 |
|--|----------------|
| Адрес на мрежата | |
| Broadcast адрес | |
| Първи използваем адрес | |
| Последен използваем адрес | |
| Брой използваеми адреси | |

**b.** Формулата е: използваеми адреси = 2^(32 – префикс) – 2. Попълнете и за **192.168.10.0/26**:

| | 192.168.10.0/26 |
|--|-----------------|
| Маска | |
| Адрес на мрежата | |
| Broadcast адрес | |
| Диапазон за устройства | |
| Брой използваеми адреси | |
| Откъде започва следващата подмрежа? | |

<details markdown="1">
<summary>Отговори за самопроверка</summary>

- **/24:** мрежа 192.168.1.0, broadcast 192.168.1.255, устройства .1–.254, общо **254**.
- **/26:** маска 255.255.255.192, мрежа 192.168.10.0, broadcast 192.168.10.63, устройства .1–.62, общо **62**; следващата подмрежа е 192.168.10.64/26.

</details>

## Част 7 (разширение): IPv6 в същата мрежа (10 мин)

**a.** На PC1 и PC2 → **Desktop** → **IP Configuration** → раздел **IPv6 Configuration** → **Static**:

| PC | IPv6 Address | Префикс |
|----|--------------|---------|
| PC1 | 2001:db8:1::10 | /64 |
| PC2 | 2001:db8:1::11 | /64 |

Запишете и адреса в полето **Link Local Address** – той се създава автоматично.

**b.** От PC1: `ping 2001:db8:1::11`.

**c.** Превключете на **Simulation**, филтър **ICMPv6**, и повторете ping.

| Въпрос | Отговор |
|--------|---------|
| Кой пакет тръгва преди Echo Request – ARP или друг? | |
| Колко бита е IPv6 адресът и колко от тях са префиксът? | |
| Как се казва полето, което заменя TTL? Каква е стойността му? | |

<details markdown="1">
<summary>Отговори за самопроверка</summary>

- Вместо ARP компютърът изпраща **Neighbor Solicitation** (ICMPv6, NDP), за да научи MAC адреса на PC2.
- Адресът е **128 бита**; префиксът /64 е мрежовата част, останалите 64 бита са за устройството.
- TTL в IPv6 се казва **Hop Limit**.
- 2001:db8::/32 е запазен за документация и обучение.

</details>

## Запомнете

- Комутаторът свързва устройства в **една** мрежа (MAC адреси, слой 2); маршрутизаторът свързва **различни** мрежи (IP адреси, слой 3).
- Интерфейсите на маршрутизатора се включват с `no shutdown`.
- Преди първия пакет към нов адрес компютърът пита с **ARP** (broadcast) и получава отговор (unicast).
