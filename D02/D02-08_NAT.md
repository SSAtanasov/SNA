# D02-08: NAT – офисът излиза в „Интернет“

> **Поток:** начинаещи | **Време:** ~75 мин | **Среда:** Cisco Packet Tracer 8.2.2
> **Задължителен минимум:** Части 1–5. **Разширение:** Част 6.
> **Връзка с курса:** лекция D02-03 (частни и публични адреси, маршрутизация към интернет с NAT); лекция D03-02 (маршрут по подразбиране); държавен въпрос 14 (частни и публични адреси, NAT).
> **Начало:** отворете `D02-07_YourName.pkt` и го запазете като `D02-08_YourName.pkt`.
> **Ако изоставате:** започнете от готовия начален файл `D02-08_Start.pkt` от преподавателя.

## Какво ще направите

Ще добавите маршрутизатор на доставчика (ISP) и сървър „в Интернет“. Компютрите в офиса имат **частни** адреси (192.168.x.x), които не се маршрутизират в Интернет. R1 ще ги подменя със своя **публичен** адрес – това е NAT. Ще видите в Simulation точно къде и как се сменя адресът.

## Кратка теория

**Частни адреси (RFC 1918)** – свободни за използване във всяка локална мрежа, но **не** се маршрутизират в Интернет:

| Диапазон | Префикс |
|----------|---------|
| 10.0.0.0 – 10.255.255.255 | 10.0.0.0/8 |
| 172.16.0.0 – 172.31.255.255 | 172.16.0.0/12 |
| 192.168.0.0 – 192.168.255.255 | 192.168.0.0/16 |

**NAT (Network Address Translation)** – маршрутизаторът на границата сменя частния адрес на изпращача с публичен и запомня това в таблица, за да върне отговора на правилния компютър. Като портиер в хотел: писмото излиза с адреса на хотела, а отговорът се връща в правилната стая.

**PAT (NAT Overload)** – много компютри споделят **един** публичен адрес; различават се по номера на портовете.

| Термин | Значение | В упражнението |
|--------|----------|----------------|
| Inside Local | Частният адрес на компютъра | адресът на PC1 (192.168.10.x) |
| Inside Global | Публичният адрес след NAT | 203.0.113.2 |
| Outside Global | Адресът на сървъра в Интернет | 198.51.100.10 |

> 203.0.113.0/24 и 198.51.100.0/24 са запазени за документация и примери. Тук играят ролята на публични адреси.

## Част 1: „Интернет“ – ISP и сървър (20 мин)

### Стъпка 1: Устройства и кабели

**a.** Добавете **Router 2911** (ISP) и **Server-PT** (Internet Server).

**b.** Кабели **Copper Cross-Over**:

```
R1  GigabitEthernet0/1 ↔ ISP GigabitEthernet0/0
ISP GigabitEthernet0/1 ↔ Internet Server FastEthernet0
```

```
[PC-та] ─ [SW1] ─ R1 (Gi0/1: 203.0.113.2) ═══ (Gi0/0: 203.0.113.1) ISP (Gi0/1: 198.51.100.1) ─ Internet Server 198.51.100.10
          частни адреси           граница: NAT                     „Интернет“
```

### Стъпка 2: ISP

```cisco
Router> enable
Router# configure terminal
Router(config)# hostname ISP
ISP(config)# no ip domain-lookup
ISP(config)# interface GigabitEthernet0/0
ISP(config-if)# ip address 203.0.113.1 255.255.255.252
ISP(config-if)# no shutdown
ISP(config-if)# exit
ISP(config)# interface GigabitEthernet0/1
ISP(config-if)# ip address 198.51.100.1 255.255.255.0
ISP(config-if)# no shutdown
ISP(config-if)# end
```

> ISP **не** получава маршрут към 192.168.0.0/16 – в Интернет частните адреси не се маршрутизират.

### Стъпка 3: Internet Server

**IP Configuration** → Static: `198.51.100.10 / 255.255.255.0`, шлюз `198.51.100.1`. **Services** → **HTTP** → **On**.

## Част 2: Без NAT (10 мин)

### Стъпка 1: Изходът на R1

```cisco
R1# configure terminal
R1(config)# interface GigabitEthernet0/1
R1(config-if)# description Link to ISP
R1(config-if)# ip address 203.0.113.2 255.255.255.252
R1(config-if)# no shutdown
R1(config-if)# exit
R1(config)# ip route 0.0.0.0 0.0.0.0 203.0.113.1
R1(config)# end
```

`ip route 0.0.0.0 0.0.0.0 203.0.113.1` е **маршрут по подразбиране**: всичко, за което R1 няма по-точен маршрут, отива към ISP.

От PC1: `ping 198.51.100.10`. В **Simulation** (филтър ICMP) проследете Echo Request и Echo Reply.

## Част 3: PAT на R1 (15 мин)

```cisco
R1# configure terminal
R1(config)# interface GigabitEthernet0/1
R1(config-if)# ip nat outside
R1(config-if)# exit
R1(config)# interface GigabitEthernet0/0.10
R1(config-subif)# ip nat inside
R1(config-subif)# exit
R1(config)# interface GigabitEthernet0/0.20
R1(config-subif)# ip nat inside
R1(config-subif)# exit
R1(config)# access-list 1 permit 192.168.10.0 0.0.0.255
R1(config)# access-list 1 permit 192.168.20.0 0.0.0.255
R1(config)# ip nat inside source list 1 interface GigabitEthernet0/1 overload
R1(config)# end
R1# copy running-config startup-config
```

| Команда | Какво прави |
|---------|-------------|
| `ip nat inside` / `ip nat outside` | Коя страна е вътрешната и коя – външната |
| `access-list 1 permit ...` | **Кои** адреси да се транслират (тук ACL само избира адреси, не филтрира трафик) |
| `ip nat inside source list 1 interface Gi0/1 overload` | Подменя ги с адреса на Gi0/1; `overload` = PAT |

## Част 5: Къде се сменя адресът (Simulation, 15 мин)

**a.** На R1: `clear ip nat translation *`. Превключете на **Simulation**, филтър **ICMP**.

**b.** От PC1 `ping 198.51.100.10`. Кликнете на пакета **на R1** и сравнете **Inbound PDU Details** и **Outbound PDU Details**.

| Къде е пакетът | Source IP | Destination IP |
|----------------|-----------|----------------|
| Echo Request: SW1 → R1 | | |
| Echo Request: R1 → ISP | | |
| Echo Reply: ISP → R1 | | |
| Echo Reply: R1 → SW1 | | |

<details markdown="1">
<summary>Отговори за самопроверка</summary>

- **Без NAT** Echo Request стига до сървъра, но Echo Reply към 192.168.10.x се губи при ISP: той няма маршрут към частните адреси.
- **С PAT** и двата компютъра излизат с **203.0.113.2**. R1 ги различава по идентификатора на ICMP (при TCP и UDP – по порта), записан в NAT таблицата.
- Request: SW1 → R1 е от **адреса на PC1** (192.168.10.x), а R1 → ISP е от **203.0.113.2**. Reply: ISP → R1 е до **203.0.113.2**, а R1 → SW1 – до **адреса на PC1**. Destination на сървъра (198.51.100.10) не се променя.

</details>

**Запазете файла като:** `D02-08_YourName.pkt` – той е изходният файл за D02-09.

## Част 6 (разширение): Интернет по име и посока отвън

**a.** На DNS сървъра (192.168.10.2) добавете A запис `web.example.com` → `198.51.100.10`. От PC3 отворете в браузъра `http://web.example.com`. Обяснете кои две услуги участват: коя дава адреса и коя го транслира.

**b.** Три различни проверки „отвън“. Разграничете кой отговаря във всяка:

| № | Тест | Резултат | Кой отговаря и защо |
|---|------|----------|---------------------|
| 1 | От Internet Server: `ping 203.0.113.2` | | |
| 2 | От PC3: Web Browser → `http://198.51.100.10` (отговорът идва отвън) | | |
| 3 | От Internet Server: `ping <адреса на PC1>` и Web Browser → `http://203.0.113.2` | | |

_Защо PAT пропуска отговорите на връзки, започнати отвътре, но не и нови връзки отвън?_ ______

**c.** Без да конфигурирате: какво трябва да се добави, за да е уеб сървърът на офиса (192.168.10.3 от Част 5 на D02-04) достъпен от Интернет през адреса на R1? (Подсказка: **статичен PAT**, наричан още port forwarding – входящите връзки към 203.0.113.2, TCP порт 80, се пренасочват към 192.168.10.3, порт 80.)

<details markdown="1">
<summary>Отговори за самопроверка (Част 6)</summary>

- **Тест 1** успява, но отговаря **самият R1** – 203.0.113.2 е неговият външен интерфейс. Тестът не доказва нищо за достъпа до вътрешните компютри.
- **Тест 2** успява: отговорът на сървъра минава отвън навътре по **съществуваща транслация**, създадена от заявката на PC3.
- **Тест 3** не успява: ISP няма маршрут към частния адрес, а за нова входяща връзка към 203.0.113.2, порт 80, в NAT таблицата няма запис.

</details>

## Запомнете

- Частните адреси (10/8, 172.16/12, 192.168/16) не се маршрутизират в Интернет.
- NAT сменя адреса на изпращача на границата; PAT позволява на много компютри да споделят един публичен адрес.
- Маршрутът по подразбиране казва на R1 къде да изпраща всичко непознато.
