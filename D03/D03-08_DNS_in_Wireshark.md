> **Връзка с курса:** лекция D01-03 (услуги на приложния слой), семинар D02-04 (DNS), семинар D02-05 (ACL и DNS), държавен въпрос 12.

## Цели на упражнението

- Прихващане на DNS запитване и отговор
- Анализ на заглавката на DNS съобщението и на записите в отговора
- Разграничаване на типовете записи A, AAAA, MX и PTR
- Разпознаване на неуспешно разрешаване на име (NXDOMAIN)
- Свързване на DNS кеша на компютъра с наблюдавания трафик

## Теоретична основа

**DNS (Domain Name System)** превръща имена (например `www.uni-sz.bg`) в IP адреси. Клиентът изпраща запитване до DNS сървъра, посочен в мрежовите му настройки, обикновено по **UDP порт 53**. При големи отговори и при прехвърляне на зони DNS използва TCP порт 53.

Най-често срещаните типове записи са:

| Тип | Номер | Съдържание |
|-----|-------|------------|
| A | 1 | IPv4 адрес на името |
| AAAA | 28 | IPv6 адрес на името |
| CNAME | 5 | Друго име (псевдоним) |
| MX | 15 | Пощенски сървър на домейна |
| PTR | 12 | Име по IP адрес (обратно разрешаване) |

Всеки отговор съдържа **TTL** – колко секунди клиентът може да пази отговора в кеша си. Докато записът е в кеша, компютърът не изпраща ново запитване. Затова преди прихващането кешът се изчиства.

> **Забележка за шифрованото DNS:** Съвременните браузъри може да използват **DNS over HTTPS** (шифровано DNS през порт 443). Windows 11 също може да е настроен за шифровано DNS (**Settings → Network & internet → DNS server assignment**), а VPN или защитен софтуер може да пренасочва запитванията. Тогава запитванията не се виждат с филтъра `dns`. Затова в упражнението генерираме DNS трафик с `ping` и `nslookup`. `nslookup` изпраща запитването сам, по UDP порт 53 до посочения сървър, и е най-сигурният начин да видите обикновен DNS.
>
> **За преподавателя:** преди занятието проверете в залата: `ipconfig /flushdns`, `ping -n 1 www.uni-sz.bg` и филтър `dns`. Ако пакети няма, студентите започват направо от Част 3.

## Част 2: Прихващане на DNS запитване от операционната система

> **Предвидете:** Колко DNS запитвания ще изпрати Windows при `ping` към име и от какъв тип ще бъдат?

### Стъпка 1: Прихващане

**a.** Стартирайте Wireshark без capture filter.

**b.** В Command Prompt изпълнете:

```
C:\>ping -n 1 www.uni-sz.bg
```

**c.** Спрете прихващането и въведете display filter `dns`.

> Ако с филтъра `dns` не виждате нищо, но ping е разрешил името, компютърът използва шифровано DNS или име от кеша. Изпълнете `ipconfig /flushdns` и повторете; ако пак няма пакети, преминете към Част 3 с `nslookup` и запишете това като наблюдение.

### Стъпка 2: Анализ на запитването

**a.** Кликнете на пакета **Standard query response** със същия Transaction ID.

**b.** Попълнете:

| Поле | Стойност |
|------|----------|
| Flags: Response | |

**c.** Проверете в кеша:

```
C:\>ipconfig /displaydns
```

_Какъв TTL показва кешът за записа и как се отнася към TTL в отговора?_ ______

<details markdown="1">
<summary>Отговори за самопроверка</summary>

- Windows изпраща обикновено две запитвания – за **A** и за **AAAA** – с различни Transaction ID.
- Портовете са произволен висок порт → **53**, протоколът е UDP.
- Отговорът има същия Transaction ID, флаг Response = 1 и Reply code **No error (0)**.
- TTL в кеша намалява с времето: това е оставащото време от TTL в отговора.

</details>

## Част 3: Запитвания с nslookup

### Стъпка 1: Различни типове записи

**a.** Стартирайте ново прихващане без capture filter.

**b.** Изпълнете последователно:

```
C:\>nslookup www.uni-sz.bg
C:\>nslookup -type=mx uni-sz.bg
C:\>nslookup nosuchhost12345.uni-sz.bg
```

**c.** Спрете прихващането и въведете display filter `dns`.

### Стъпка 2: Анализ

- _Преди запитването за www.uni-sz.bg nslookup изпраща запитване от тип PTR. За какво име е то и защо nslookup го прави?_ ______
- _Какво съдържа отговорът на запитването от тип MX?_ ______
- _Какъв е Reply code на запитването за несъществуващото име?_ ______
- _Колко записа (Answer RRs) има в отговора за несъществуващото име?_ ______

<details markdown="1">
<summary>Отговори за самопроверка</summary>

- nslookup първо пита за името на самия DNS сървър (PTR за `x.x.x.x.in-addr.arpa`), за да го покаже на реда „Server:“.
- MX отговорът съдържа име на пощенски сървър и приоритет (Preference).
- За несъществуващо име Reply code е **No such name (3)**, т.е. NXDOMAIN, а Answer RRs е 0.

</details>

## Практически съвети за Wireshark

```
dns                                   # Всички DNS съобщения
dns.flags.response == 0               # Само запитвания
dns.flags.response == 1               # Само отговори
dns.qry.name contains "uni-sz"        # Запитвания за конкретен домейн
dns.qry.type == 28                    # Само AAAA запитвания
dns.flags.rcode == 3                  # Неуспешни (NXDOMAIN)
dns.time > 0.1                        # Бавни отговори (над 100 ms)
```

**Statistics → DNS** показва обобщено броя на запитванията, типовете и времената за отговор.
