> **Задължителен минимум:** Части 1–3. **Разширение:** Част 4.
> **Връзка с курса:** лекция D01-04 (ICMP и диагностика), D03-04 (Част 5 – TTL), държавен въпрос 14.

## Цели на упражнението

- Разпознаване на основните типове ICMP съобщения
- Наблюдаване на ICMP Time Exceeded при изтичане на TTL
- Обяснение как работи `tracert` на ниво пакети
- Наблюдаване на поведението при флаг Don't Fragment и прекалено голям пакет

## Теоретична основа

**ICMP (Internet Control Message Protocol)** пренася съобщения за грешки и диагностика на мрежовия слой. ICMP се капсулира в IPv4 пакет с Protocol = 1. Всяко съобщение има поле **Type** и поле **Code**:

| Type | Code | Значение |
|------|------|----------|
| 0 | 0 | Echo Reply (отговор на ping) |
| 3 | 0 | Destination Unreachable – мрежата е недостижима |
| 3 | 1 | Destination Unreachable – хостът е недостижим |
| 3 | 3 | Destination Unreachable – портът е недостижим |
| 3 | 4 | Destination Unreachable – нужна е фрагментация, но DF е зададен |
| 3 | 13 | Destination Unreachable – комуникацията е забранена административно (например от ACL) |
| 8 | 0 | Echo Request (ping) |
| 11 | 0 | Time Exceeded – TTL е изтекъл по пътя |

Съобщенията за грешка (Type 3 и 11) съдържат в себе си **заглавката и началото на оригиналния пакет**, който е предизвикал грешката. Така изпращачът разбира за кой свой пакет се отнася съобщението.

**Как работи tracert (Windows):**

1. Изпраща ICMP Echo Request с **TTL = 1**. Първият маршрутизатор намалява TTL до 0, отхвърля пакета и връща **Time Exceeded**. Така се научава адресът на първия маршрутизатор.
2. Повтаря с TTL = 2, 3, … По три пакета за всяка стойност.
3. Когато пакетът стигне до целта, тя връща **Echo Reply** и tracert спира.

> Linux и macOS по подразбиране използват `traceroute`, който изпраща UDP пакети вместо ICMP Echo Request. Принципът с TTL е същият.

## Част 1: TTL, изтекъл на първия маршрутизатор

> **Предвидете:** Какво ще отговори шлюзът, ако изпратите ping към 8.8.8.8 с TTL = 1?

**a.** Стартирайте прихващане без capture filter и въведете display filter `icmp`.

**b.** В Command Prompt изпълнете:

```
C:\>ping -n 2 -i 1 8.8.8.8

Pinging 8.8.8.8 with 32 bytes of data:
Reply from 192.168.1.1: TTL expired in transit.
Reply from 192.168.1.1: TTL expired in transit.
```

Параметърът `-i 1` задава TTL = 1.

**c.** Спрете прихващането.

**d.** Кликнете на пакета **Time-to-live exceeded** и разгънете **Internet Control Message Protocol**.

| Поле | Стойност |
|------|----------|
| Source IP на ICMP съобщението | |
| Type / Code | |
| Вътрешен пакет: Source IP / Destination IP | |
| Вътрешен пакет: Time to Live | |

- _Кое устройство е изпратило Time Exceeded?_ ______
- _Каква стойност на TTL наблюдавате във вложената IP заглавка? Как я обяснявате?_ ______
- _Сравнете стойността с колегата до вас. Еднаква ли е и от какво може да зависи?_ ______

<details markdown="1">
<summary>Отговори за самопроверка</summary>

- Source е default gateway; Type = 11, Code = 0.
- Вътрешният пакет е вашият Echo Request: от вашия адрес към 8.8.8.8.
- Най-често ще видите **TTL = 1**: маршрутизаторът връща началото на пакета така, както го е **получил**. Намаляването до 0 е причината пакетът да бъде отхвърлен.
- Стойността обаче не е гарантирана. RFC 1812 допуска маршрутизаторът да е променил заглавката (включително TTL) преди да открие грешката, затова някои устройства връщат TTL = 0. И двете наблюдения са правилни, ако са обяснени.

</details>

## Част 2: tracert стъпка по стъпка

**a.** Стартирайте ново прихващане без capture filter с display filter `icmp`.

**b.** Изпълнете:

```
C:\>tracert -d 8.8.8.8
```

Параметърът `-d` изключва обратното разрешаване на адресите в имена, за да няма допълнителен DNS трафик.

**c.** След като tracert завърши, спрете прихващането.

**d.** Въведете display filter, който показва само вашите Echo Request:

```
icmp.type == 8
```

Кликнете на първите шест пакета и запишете TTL на всеки (**Internet Protocol Version 4 → Time to Live**).

| Пакет | TTL |
|-------|-----|
| 1 | |
| 2 | |
| 3 | |
| 4 | |
| 5 | |
| 6 | |

**e.** Въведете display filter:

```
icmp.type == 11
```

_Колко различни адреса изпращат Time Exceeded? Съвпадат ли с адресите в изхода на tracert?_ ______

**f.** Въведете display filter `icmp.type == 0` и проверете кой изпраща Echo Reply.

- _На кой ред от tracert съответства Echo Reply?_ ______
- _Ако на някой ред tracert показва `* * *`, какво виждате във Wireshark за тази стойност на TTL?_ ______

<details markdown="1">
<summary>Отговори за самопроверка</summary>

- TTL на Echo Request нараства: 1, 1, 1, 2, 2, 2, … (по три пакета за всяка стойност).
- Всеки маршрутизатор по пътя връща Time Exceeded; броят на адресите е броят на маршрутизаторите, които отговарят.
- Echo Reply идва от целта (8.8.8.8) и съответства на последния ред.
- При `* * *` има Echo Request с тази стойност на TTL, но няма отговор: маршрутизаторът не изпраща Time Exceeded или ги ограничава.

</details>

## Част 4 (разширение): Флаг Don't Fragment и размер на пакета

> **Предвидете:** Колко най-много байта данни може да носи ping с DF, ако MTU на Ethernet е 1500 байта?

**a.** Стартирайте прихващане с display filter `icmp`.

**b.** Изпълнете:

```
C:\>ping -n 1 -f -l 1472 8.8.8.8
C:\>ping -n 1 -f -l 1473 8.8.8.8
```

Параметърът `-f` задава флага Don't Fragment, а `-l` – броя байтове данни.

**c.** Отговорете:

- _Какъв е Total Length на първия Echo Request във Wireshark?_ ______
- _Какво съобщение показва Windows при 1473 байта? Има ли пакет във Wireshark за тази команда?_ ______

> **Забележка:** Windows проверява размера спрямо MTU на собствения интерфейс и може да покаже „Packet needs to be fragmented but DF set.“, без изобщо да изпрати пакет. Ако по-малко MTU има по-нататък по пътя, маршрутизаторът връща ICMP **Type 3, Code 4**. Така работи Path MTU Discovery.

<details markdown="1">
<summary>Отговор за самопроверка</summary>

1472 байта данни + 8 байта ICMP заглавка + 20 байта IPv4 заглавка = 1500 байта, т.е. точно MTU. Total Length на пакета е 1500.

</details>

## Практически съвети за Wireshark

```
icmp                                  # Всички ICMP съобщения
icmp.type == 8                        # Echo Request
icmp.type == 0                        # Echo Reply
icmp.type == 11                       # Time Exceeded
icmp.type == 3                        # Destination Unreachable
icmp.type == 3 && icmp.code == 13     # Забранено административно (ACL)
icmp.resp_not_found                   # Echo Request без отговор
```
