# D03-12: Трафикът през погледа на администратора – статистики във Wireshark

> **Поток:** напреднали | **Време:** ~45 мин | **Среда:** Windows 10/11, Wireshark 4.6.x с Npcap
> **Задължителен минимум:** Части 1–3. **Разширение:** Част 4.
> **Връзка с курса:** администрирането на мрежата – наблюдение, базово ниво на трафика (baseline) и откриване на отклонения; всички упражнения D03-01 до D03-11.

## Цели на упражнението

- Обобщаване на голямо прихващане без преглед пакет по пакет
- Определяне кои протоколи и кои устройства генерират най-много трафик
- Изграждане на графика на трафика във времето
- Използване на Expert Information за бързо откриване на проблеми

## Теоретична основа

Мрежовият администратор рядко гледа отделни пакети. Първо пита: **какво** има в мрежата, **кой** говори с **кого**, **колко** и **кога**. Wireshark отговаря на тези въпроси с менюто **Statistics**:

| Инструмент | Отговаря на въпроса |
|------------|---------------------|
| Capture File Properties | Колко време, колко пакета и байта, каква средна скорост |
| Protocol Hierarchy | Какъв дял от трафика е всеки протокол |
| Conversations | Кои двойки адреси обменят най-много данни |
| Endpoints | Кои отделни адреси участват най-много |
| I/O Graphs | Как се променя трафикът във времето |
| Expert Information (менюто Analyze) | Има ли грешки, повторно изпращане, отказани връзки |

Нормалната картина на трафика се нарича **базово ниво (baseline)**. Ако администраторът я познава, той бързо забелязва отклонение: внезапен поток от broadcast, неочакван адрес или много повторно изпращане.

> Базовото ниво се изгражда от **много проби** в различно време и от определена **точка на прихващане** (например огледален порт на комутатора). В това упражнение правите **първа проба** от един компютър – начало за сравнение, а не базово ниво на цялата зала.

> **Етика и правила:** Прихващайте само трафика на собствения си компютър в учебната зала. Прихващането съдържа адреси, имена на сайтове и понякога лични данни. Не публикувайте и не споделяйте файла извън упражнението.

## Необходими ресурси

- 1 PC (Windows 10/11)
- Wireshark 4.6.x с Npcap
- Браузър и достъп до Интернет

---

## Част 1: Прихващане на нормален трафик

**a.** Стартирайте прихващане без capture filter.

**b.** В продължение на около 3 минути работете обичайно: отворете 3–4 сайта, пуснете кратко видео, изпълнете `ping 8.8.8.8` и `nslookup www.uni-sz.bg`.

**c.** Спрете прихващането и го запазете: **File → Save As**, формат **pcapng**, име `proba1_<вашето_име>.pcapng`.

> **Предвидете:** Кой протокол според вас ще заема най-голям дял от байтовете и защо?

## Част 2: Обобщение на прихващането

### Стъпка 1: Capture File Properties

Отворете **Statistics → Capture File Properties** и попълнете:

| Параметър | Стойност |
|-----------|----------|
| Продължителност (Elapsed) | |
| Брой пакети | |
| Брой байтове | |
| Средна скорост (Average bits/s) | |

### Стъпка 2: Protocol Hierarchy

Отворете **Statistics → Protocol Hierarchy**.

> Процентите са по нива и **не се събират до 100 %**. Един пакет съдържа няколко протокола едновременно (например Ethernet → IPv4 → UDP → DNS) и се брои във всеки от тях. Сравнявайте само протоколи от едно ниво, например TCP с UDP.

| Протокол | Дял от пакетите (%) | Дял от байтовете (%) |
|----------|---------------------|----------------------|
| IPv4 | | |
| IPv6 | | |
| TCP | | |
| UDP | | |
| QUIC | | |
| TLS | | |
| DNS | | |
| ARP | | |

- _Защо делът на DNS по пакети и по байтове е толкова различен?_ ______

<details markdown="1">
<summary>Отговор за самопроверка</summary>

DNS пакетите са много, но малки (обикновено под 200 байта). Видеото и уеб страниците са малко на брой връзки, но с големи пакети (около 1500 байта), затова доминират по байтове.

</details>

## Част 3: Кой с кого говори

### Стъпка 1: Conversations

Отворете **Statistics → Conversations**, раздел **IPv4**. Сортирайте по колоната **Bytes** (низходящо).

| № | Address A | Address B | Packets | Bytes |
|---|-----------|-----------|---------|-------|
| 1 | | | | |
| 2 | | | | |
| 3 | | | | |

- _Кой е отдалеченият адрес с най-много трафик? Кликнете с десен бутон → **Apply as Filter → Selected → A ↔ B** и разберете от SNI или DNS за кой сайт става дума._ ______

### Стъпка 2: Endpoints

Отворете **Statistics → Endpoints**, раздел **Ethernet**.

- _Колко различни MAC адреса участват в прихващането?_ ______
- _Кой MAC адрес е на шлюза и как го разпознахте?_ ______

### Стъпка 3: Broadcast и multicast

Въведете display filter:

```
eth.dst == ff:ff:ff:ff:ff:ff
```

- _Колко broadcast рамки има и от кои протоколи са (ARP, DHCP, NetBIOS и др.)?_ ______

Въведете:

```
eth.dst.ig == 1
```

(IG бит = 1 означава групов адрес: broadcast или multicast.)

- _Колко рамки са broadcast или multicast общо? Какъв процент от всички?_ ______

## Част 4 (разширение): Трафикът във времето и Expert Information

### Стъпка 1: I/O Graphs

**a.** Отворете **Statistics → I/O Graphs**.

**b.** Оставете графиката **All Packets** и добавете (бутон **+**) нова графика с display filter `dns`. Сменете **Y Axis** на **Bytes** за първата графика.

- _В кой момент трафикът е най-голям и на какво действие от Част 1 съответства?_ ______
- _Предшестват ли DNS запитванията пиковете в трафика? Защо?_ ______

## Обяснете сами (без готов отговор)

1. Как бихте открили с инструментите от това упражнение компютър в залата, който изпраща необичайно много ARP заявки?

## Заключение

В това упражнение използвахме статистиките на Wireshark, за да видим цялостната картина на трафика: кои протоколи преобладават, кои устройства обменят най-много данни, как трафикът се променя във времето и дали има проблеми.
