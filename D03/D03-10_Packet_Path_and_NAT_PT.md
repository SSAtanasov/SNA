# D03-10: Пътят на пакета през шлюз и NAT (Packet Tracer, PDU)

> **Поток:** напреднали | **Време:** ~50 мин | **Среда:** Packet Tracer 8.2.2
> **Задължителен минимум:** Части 1–3. **Разширение:** Част 4.
> **Връзка с курса:** лекции D02-02 (Ethernet, MAC), D02-03 (IPv4, NAT), D03-02 (маршрутизация); семинар D02-08 (NAT); държавни въпроси 13 и 14.

## Цели на упражнението

- Проследяване на един и същ пакет през няколко мрежи в режим Simulation
- Установяване кои адреси се сменят на всеки преход (hop) и кои се запазват
- Наблюдаване на ARP в отделните сегменти
- Наблюдаване на транслацията на адреса на изхода през NAT (PAT)

## Теоретична основа

Когато пакетът преминава от една мрежа в друга:

- **MAC адресите се сменят на всеки сегмент.** Всеки маршрутизатор изгражда нова Ethernet рамка: source е неговият изходящ интерфейс, destination е следващото устройство.
- **IP адресите при обикновена маршрутизация се запазват** от източника до целта.
- **TTL намалява** с 1 на всеки маршрутизатор.
- **NAT** е изключение: маршрутизаторът на границата сменя частния **source** IP адрес (Inside Local) с публичен (Inside Global). При PAT (overload) се сменя и source портът, ако е нужно, а за ICMP – идентификаторът.

Тези четири правила са в основата на отговорите за въпроси 13 и 14 от държавния изпит.

## Топология

Използвайте вашата топология от семинар D02-08 (NAT) или изградете следната минимална топология:

```
 PC0 ──── SW0 ──── R1 ═══════════ R2 ──── Server0
 192.168.1.10      G0/0  G0/1   G0/0  G0/1      198.51.100.10
 GW .1           .1/24   .1/30  .2/30  .1/24     GW 198.51.100.1
                 (inside) (outside)
```

| Устройство | Интерфейс | IP адрес / маска | Шлюз |
|------------|-----------|------------------|------|
| PC0 | Fa0 | 192.168.1.10/24 | 192.168.1.1 |
| R1 (2911) | G0/0 | 192.168.1.1/24 (NAT inside) | – |
| R1 (2911) | G0/1 | 203.0.113.1/30 (NAT outside) | – |
| R2 (2911) | G0/0 | 203.0.113.2/30 | – |
| R2 (2911) | G0/1 | 198.51.100.1/24 | – |
| Server0 | Fa0 | 198.51.100.10/24 | 198.51.100.1 |

> Мрежите 203.0.113.0/24 и 198.51.100.0/24 са запазени за документация и тук играят ролята на „Интернет“.

**Конфигурация на R1:**

```
R1(config)# interface g0/0
R1(config-if)# ip address 192.168.1.1 255.255.255.0
R1(config-if)# ip nat inside
R1(config-if)# no shutdown
R1(config-if)# interface g0/1
R1(config-if)# ip address 203.0.113.1 255.255.255.252
R1(config-if)# ip nat outside
R1(config-if)# no shutdown
R1(config-if)# exit
R1(config)# access-list 1 permit 192.168.1.0 0.0.0.255
R1(config)# ip nat inside source list 1 interface g0/1 overload
R1(config)# ip route 0.0.0.0 0.0.0.0 203.0.113.2
```

**Конфигурация на R2:**

```
R2(config)# interface g0/0
R2(config-if)# ip address 203.0.113.2 255.255.255.252
R2(config-if)# no shutdown
R2(config-if)# interface g0/1
R2(config-if)# ip address 198.51.100.1 255.255.255.0
R2(config-if)# no shutdown
```

> R2 не се нуждае от маршрут към 192.168.1.0/24: след NAT пакетите идват от 203.0.113.1, а тази мрежа е директно свързана с R2. Помислете какво би станало без NAT.

## Част 1: Подготовка

**a.** Проверете връзката в режим **Realtime**: от PC0 изпълнете `ping 198.51.100.10`. Ако първите отговори изтекат (Request timed out), повторете – това е времето за ARP.

**b.** Изчистете кешовете, за да видите целия процес:
- на PC0: `arp -d`
- на R1 и R2: `clear arp-cache`
- на R1: `clear ip nat translation *`

**c.** Превключете в режим **Simulation**. В **Edit Filters** оставете само **ARP** и **ICMP**.

> **Предвидете:** Попълнете колоната „Очакване“ в таблицата от Част 2, преди да пуснете пакета.

---

## Част 2: Проследяване на Echo Request

**a.** От PC0 изпълнете `ping -n 1 198.51.100.10` (в Command Prompt на PC0).

**b.** Натискайте **Capture/Then Forward** и кликвайте на PDU на всяко устройство. В прозореца на PDU отворете **Inbound PDU Details** и **Outbound PDU Details**.

**c.** Попълнете за ICMP Echo Request на всеки сегмент:

| Сегмент | Очакване | Src MAC | Dst MAC | Src IP | Dst IP | TTL |
|---------|----------|---------|---------|--------|--------|-----|
| PC0 → R1 (LAN) | | | | | | |
| R1 → R2 (връзката 203.0.113.0/30) | | | | | | |
| R2 → Server0 | | | | | | |

**d.** Отговорете:

- _Колко ARP обмена видяхте и в кои сегменти?_ ______
- _Кои адреси се смениха между първия и втория сегмент? Кое устройство ги смени?_ ______
- _Кои адреси се смениха между втория и третия сегмент?_ ______
- _С колко намаля TTL от PC0 до Server0?_ ______

## Част 3: Echo Reply и таблицата на NAT

**a.** Продължете с **Capture/Then Forward**, докато Echo Reply се върне до PC0. Попълнете:

| Сегмент | Src IP | Dst IP | Src MAC | Dst MAC |
|---------|--------|--------|---------|---------|
| Server0 → R2 | | | | |
| R2 → R1 | | | | |
| R1 → PC0 | | | | |

**b.** Превключете в **Realtime** и на R1 изпълнете:

```
R1# show ip nat translations
```

Попълнете реда за ICMP:

| Pro | Inside global | Inside local | Outside local | Outside global |
|-----|---------------|--------------|---------------|----------------|
| icmp | | | | |

- _На кой адрес отговаря Server0 – на 192.168.1.10 или на 203.0.113.1? Защо?_ ______
- _Как R1 разбира, че Echo Reply е за PC0?_ ______

<details markdown="1">
<summary>Отговори за самопроверка</summary>

- ARP има в трите сегмента: PC0 търси MAC на 192.168.1.1, R1 търси MAC на 203.0.113.2, R2 търси MAC на 198.51.100.10.
- Между първия и втория сегмент R1 сменя и двата MAC адреса, **и** source IP: 192.168.1.10 → 203.0.113.1 (NAT). Destination IP остава 198.51.100.10.
- Между втория и третия сегмент R2 сменя само MAC адресите; IP адресите остават.
- TTL намалява с 2 (два маршрутизатора).
- Server0 отговаря на **203.0.113.1** – той не вижда частния адрес. R1 намира в NAT таблицата записа с Inside global 203.0.113.1 и идентификатора на ICMP и връща destination на 192.168.1.10.

</details>

## Част 4 (разширение): Без NAT

**a.** На R1 премахнете NAT:

```
R1(config)# no ip nat inside source list 1 interface g0/1 overload
```
